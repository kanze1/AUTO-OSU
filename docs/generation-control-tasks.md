# 高难度与 highlight 的下一轮任务

已完成[实际星级测量与固定对照](difficulty-evaluation.md)。0.3.0.dev3 已实现 Q2.1–Q2.4 和 H1.1–H1.4 的实验接口，并准备本地软件与对照谱面供验收，详见[实现与实测结果](generation-controls.md)。以下按依赖推进，不设交付时间。已有模型保持 v0；新增高难度预设和替换权重都需要独立验收。

## Q2：高难度控制

| 顺序 | 任务 | 具体改动或实验 | 验收 |
| --- | --- | --- | --- |
| Q2.1 | 区分密度不足和跨度不足 | 在开发歌曲上固定参考 timing、种子、Insane 参数，分别改变密度条件和星级条件；记录实际 SR、aim / speed、NPS、连打长度和局部峰值 | 给出逐歌响应和失败样本；不能只报平均提升 |
| Q2.2 | 接通局部密度曲线 | 让节奏模型接受时间曲线；使用训练时相同的前后 8 小节窗口与边缘归一化；保留静段和恢复段 | 同一曲线的常数版本与现有常数条件一致；检查段落响应、边界和短歌 |
| Q2.3 | 恢复可选距离条件 | 先从无距离条件的一次坐标采样取得每个 token 的参考位置，再计算逐 token 距离，缩放物件头进入距离后做第二次采样；滑条内部锚点和尾部保留各自距离 | 与完全无距离、距离倍率 1.0、较小 / 较大倍率做对照；报告额外耗时与曲线变形 |
| Q2.4 | 有上限的候选筛选 | 在已验证有效的条件范围内，最多生成 3 个候选，按实际星级接近程度与结构约束选择；保留全部候选指标 | 未达标明确显示实际结果；不得靠异常局部尖峰凑星级 |
| Q2.5 | 冻结候选后验收 | 先验收 6–7★，再考虑 7–8★；在预留歌曲上评估一次，并进行盲测 | 至少 80% 在目标 ±0.5★，同时结构和手感不过退；不达标则继续标为实验能力 |

**距离条件的实现约束已经查清：** `coord/osu_diffusion/utils/data_loading.py` 的 `calc_distances()` 在原始 512×384 像素坐标中计算当前 token 到前一个 token 的欧氏距离，首 token 到 (256, 192)。距离直接进入 128 维 sinusoidal embedding，没有按 CS 归一化，也没有乘时间所用的 0.1。顺序包含圈、转盘、滑条头、每个锚点、滑条尾。不能把一个“跳跃距离”常数填给整个序列。默认推理仍使用零距离；新控制以两次采样恢复距离条件，倍率 1.0 的有距离条件也不是无条件基线。

**短爆点另设任务：** 现有密度标签平滑到前后 8 小节，不能把逐秒尖峰曲线直接当成已训练过的控制能力。如果段落对比在这一尺度就失败，先查条件服从性；如果长段有效、短段无效，再评估更细标签和训练。

## H1：highlight 控制

| 顺序 | 任务 | 具体改动或实验 | 验收 |
| --- | --- | --- | --- |
| H1.1 | 手动段落计划 | 定义音频时间的开始、结束、强度、进入和释放时长；统一换算到谱面时间，拒绝越界 / 冲突区间 | 人工指定的段落准确落在输出中；CLI、独立 worker 和批量使用同一计划格式 |
| H1.2 | 段落驱动生成 | 先连接已验证的局部密度与跨度，再连接 combo、hitsound 和 kiai；SV 单独控制 | kiai 开关不能代替音乐强调；非 highlight 段保留恢复空间 |
| H1.3 | 四组消融 | 同歌同种子：原版、手动段落+密度、手动段落+密度/跨度、自动段落+全部控制 | 比较区间内外 NPS、spacing、aim / speed strain，检查进入 / 结束衔接和人工偏好 |
| H1.4 | 自动定位 | 先在现有响度上增加鼓 / 和声 onset 与小节边界，再独立评估重复段落特征；记录置信度 | 对照人工标注，低置信度允许无 highlight 或手动覆盖；强压缩歌曲和短爆点单列失败 |
| H1.5 | 局部重生成 | 在完整段落控制通过后处理上下文窗口、跨界滑条和局部随机数 | 修改一段时，其余已接受段落和边界保持可验证的稳定 |

## 验收素材与记录

开发集和预留集已按音频哈希冻结。候选策略在 8 首开发歌曲上冻结后，已使用 24 首预留歌曲分别检查参考 timing 和自动 timing，结果记录在[验收报告](generation-controls.md)。该预留集已使用，后续调参后的独立测试必须另选新歌曲。当前没有人工 highlight 标签，也没有盲测结果。参考谱面的 kiai 可以作为辅助比较，但不能冒充人工听音标注。

每首用于 H1 验收的歌需要记录：主要 highlight 的音频起止时间、允许偏差、强度、是否存在多个合理位置，以及听音者意见。盲测比较段落位置、强弱对比、流畅度和非 highlight 部分；实际客户端导入 / 试玩单独记录。纯数值或 parser 通过不替代这些结果。

在这些验收完成前，README 保留“实验 / 计划”状态，不声明稳定生成目标星级或自动识别音乐高潮。

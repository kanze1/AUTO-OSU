# 物件级空间原型：对照与重设计决定

2026-10-08，关联 [M3 / Issue #12](https://github.com/kanze1/AUTO-OSU/issues/12)。结论：表示修正已经落实，但冻结旧 DiT、仅训练输入残差的方案未通过验证门槛；不扩大正式训练、不替换默认 coord v0。

## 完成的修正

- [物件表示](../autoosu/ml/coord_objects.py)为每个圆圈、滑条和转盘建立节点，记录锚点归属。滑条单程终点与实际出口分开：偶数次遍历退出在头部，奇数次退出在终点。旧编码的最后两种折返类别分别表示大于等于 4 的偶数、大于等于 5 的奇数，并非精确次数。
- 当前带噪头部、实际出口、前一出口到下一头部的位移进入物件编码器；输入不读取目标坐标。通过归属索引将物件条件送回坐标 token，滑条控制点使用相对头部表示。
- 裁剪保留完整物件，边界处明确前驱未知；保留物件间负间隔，不删除重叠物件。孤立控制点、截断物件和旧 tokenizer 无法表示的滑条直接报错。
- 音频和物件分支仍通过零初始化残差接入冻结基座。保存格式为 prototype/2，继续读取此前 prototype/1 音频权重；基座身份检查保留。当前不是完整的新几何骨干，也没有跨窗空间计划。

## 固定输入对照

采用既有 32 歌语料中的 8 首开发歌，6 首训练、2 首验证；24 首 heldout 未用于此次选型。基座历史训练重叠未知，因此这些数据不构成独立泛化测试。每歌四个最多 128 token 的完整物件片段；相同输入、训练噪声顺序和学习率 0.0002。验证固定 24 个噪声样本，时刻为 100/500/900，CPU 随机种子 1949。

两方案各训练 256 步、使用 20261008 和 20261009 两个种子，并在 64 步留验证记录。损失仍为旧 DDPM 目标；物件平均误差作为额外指标，未同时改动训练损失。完整来源、代码哈希、逐片段结果及采样身份见[机器可读记录](coordinate-object-pilot-20261008.json)。

| 方案 | 种子 | 64 步验证 MSE | 256 步验证 MSE | 相对旧模型 |
|---|---:|---:|---:|---:|
| 旧 coord v0 | — | 0.151252 | 0.151252 | 基线 |
| 局部＋整曲音频 | 20261008 | 0.151702 | 0.152570 | +0.87% |
| 加物件条件 | 20261008 | 0.151899 | 0.154234 | +1.97% |
| 局部＋整曲音频 | 20261009 | 0.151697 | 0.152159 | +0.60% |
| 加物件条件 | 20261009 | 0.151964 | 0.152522 | +0.84% |

MSE 越低越好。全部新方案均退化，物件平均 MSE 也未超过旧基座。完整物件裁剪改变了输入，不能与首轮任意裁剪的 0.144963 直接比较。音频时间移位未稳定变差，尚无稳定的有效音乐依赖证据。

完成后追加固定训练集探针：CPU 噪声种子 314159、24 个训练片段、三个相同噪声时刻，共 72 个样本。旧基座 MSE 为 0.162173；音频方案两个种子为 0.159891 / 0.160767，物件方案为 0.158786 / 0.160129。四者训练集改善而验证退化，支持小样本过拟合的解释；仍不能排除冻结骨干、注入位置、训练目标与可玩性指标不一致等因素。探针源代码及结果保存在机器可读记录中。不同训练步的随机 loss 不作为收敛证据。

四个模型均在第一段真实验证节奏上执行了同种子、100 步纯噪声坐标采样，输出数值有限。四个结果的原始头部越界数分别为 1、4、0、0；这是排查信息，未运行同条件基座采样，不能用于证明越界改善。未进行滑条拟合、`.osu` 导出或客户端试玩，不能称为可玩性验收。全套测试 220 项通过。

## 调查后的架构选择

[上游 osu-diffusion](https://github.com/OliBomby/osu-diffusion#purpose)明确把音频到节奏与间距、部分谱面到坐标分为两部分。我们的默认推理将距离条件置零，而上游训练支持距离条件丢弃；这不是接口错误，却提示值得单独验证显式运动规划的价值。[Lodge](https://arxiv.org/abs/2403.10518)在音乐到舞蹈任务采用粗到细的全局和局部生成；它仅提供设计参考，不是 osu! 质量证据。

下一轮设计假设为：**音乐与固定节奏 → 可学习的物件运动计划 → 物件级坐标及滑条几何**。

1. 从人工谱的实际退出位置提取下一物件移动距离、方向关系和滑条局部几何监督。预测条件分布，保留多种合理布局；不以硬编码距离/转角阈值规定 jump、stream 或乐句类型。
2. 先做真实计划条件的上界对照，判断坐标模型能否利用该信息；真实计划只用于诊断，不能当作音频生成结果。再比较无计划、预测计划与联合微调，使用相同歌曲分组、预算和多种子。
3. 旧模型距离槽表示相邻 token 的距离，新的物件出口距离不能直接塞进去。明确新字段与已知状态掩码，并用训练过的新条件接口接入；训练时包含预测计划或受扰计划，评估训练与推理条件的差异。
4. 保留绝对头部和滑条相对几何。比较冻结与联合微调，避免把本轮失败单独归因于骨干大小。长上下文训练与跨窗已知空间状态需另做消融。
5. 用移动分布、多样性、滑条修复量和同节奏盲测共同选择。开发阶段达标后再使用 heldout，生成完整谱并做独立解析与客户端试玩；去噪 MSE 本身不能决定审美质量。

## 复现

原始结果保存在 Git 外的 `out/coord-object-20261008/pilot`，来源清单为其上级 `sources.json`；权重、歌曲和坐标不入 Git。使用声明的训练依赖运行：

```powershell
python scripts/coord_context_pilot.py --recipe <sources.json> --base <coord_v0.pt> --out <new-directory> --steps 256 --variants local-and-song object-aware --seeds 20261008 20261009 --milestones 64
```

对照脚本及源码哈希保存在记录中，完整物件片段身份在 `crops` 字段。训练集追加探针是事后诊断，不用于选择最优 checkpoint；没有使用测试集来回调参。

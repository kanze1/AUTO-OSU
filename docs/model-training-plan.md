# 带标签模型的重训排期

当前发布权重仍是 `rhythm_v0.pt` / `coord_v0.pt`。0.3.0rc2 的[谱面偏好](skill-preferences.md)使用已有密度、距离条件和候选筛选；**带标签训练尚未开始**。这里按依赖列出下一版任务，不设日期或耗时承诺。实际状态以 [TASKS.md](TASKS.md) 为准。

## M1.1：标签和数据审计

先统一标签含义：跳跃、短串、长串、耐力、滑条技巧、阅读等；首轮只选数据和标注质量足够的类别，允许多标签，也允许未知。短串与长串分开统计，不能用高密度直接代替连打标签。滑条数量偏好与滑条技巧分开。

- 建立数据清单：谱面和音频身份、实际星级、BPM、物件组成、标签来源、版本与使用条件；统计缺失、分歧和各星级段覆盖。
- 人工复核抽样，记录标注者一致性；社区标签与自动提取特征作为不同证据。缺标签不等于负标签，第一轮不提供缺乏负样本支持的“排除某技能”。
- 按音频内容分组，并检查同曲不同编码、剪辑和近重复，冻结训练 / 开发 / 测试清单。已经用于调参或验收的歌曲单列；v0 训练集交叠不明时明确标注。
- 保留静段、恢复段和高星样本，检查标签与星级、BPM、谱师的混淆，避免“偏跳跃”仅学成“更高星”。

产物：标签规范、数据统计、人工抽检记录、冻结划分及来源清单。标签质量或覆盖不足时先补数据，不直接启动完整重训。

## M1.2：小规模条件训练与消融

依赖 M1.1。在独立实验分支保留 v0 对照，先验证标签是否带来可重复的控制增益，再决定扩大训练规模。比较从 v0 微调与必要时重训的成本和结果，不默认全量从头训练。

1. 节奏模型增加技能标签条件，使用缺标签掩码和条件 dropout；保持现有星级、密度输入可用，检查无标签模式是否退化。
2. 坐标模型增加相同标签条件，保留逐 token 距离语义。比较仅节奏、仅坐标、双模型标签，以及当前条件版，分离标签本身的增益。
3. 单独评估细分节奏网格、滑条长度和段落条件，避免一次更换所有表示后无法归因。只有现有网格限制目标技能时才推进更细网格。

产物：可复现配置、数据版本、种子、曲线和逐歌对照。新 checkpoint 使用独立版本，模型文件不进 Git，不覆盖 v0。

## M1.3：冻结模型后的独立验收

依赖 M1.2。在开发集冻结权重、采样配置、候选策略和判定阈值，再使用预留集一次验收；修改策略后另取测试集。

- 同歌、同种子，比较无标签 / 正向标签 / 当前条件版，按**实际星级接近**分组报告技能响应和未满足率；分开短串、长串及不同星级段，不能只报平均星级提升。
- 参考 timing 与自动 timing 分开；6–7★、7–8★及更高星逐档检查，不把较低难度结论直接推广。
- 盲测记录偏好是否清楚、节奏自然度、可读性、疲劳与恢复段；人工 highlight 位置、客户端导入、试玩和编辑器另存分别留证。
- 回归综合模式、手动密度 / 跨度、四种 highlight、单首 / 批量、CPU / GPU、来源标签和新图水印；独立 parser 检查滑条路径与结构。

产物：冻结测试报告和人工评审记录。客观响应、目标星级和结构验收沿用既有口径；细分标签、人评样本量及通过标准在测试前登记。未通过时保留实验状态，不替换默认权重。

## M1.4：新权重候选版与发布

依赖 M1.3 通过。更新 checkpoint 格式、标签字典、下载校验与运行时兼容检查；界面仅展示该模型确实支持的标签。验证无标签旧模型可继续使用，保存的生成计划带模型 / 标签版本，缺失能力明确提示。

先提供候选应用和对照谱面，确认使用体验后再发布新默认权重。发布记录包含模型身份、训练数据版本、验收报告和回退方式；README 分清“条件版已实现”“标签训练已完成”“新权重已发布”。

## 与高难度和 highlight 的关系

Q2.5 继续解决自动 timing 与高星条件响应；H1.4 继续收集真实听音区间，H1.5 的局部重生成仍在段落验收之后。标签数据审计可以先行，不因排入重训就把这些现有任务标为完成。具体缺口见[高难度与 highlight 任务](generation-control-tasks.md)。

# 模型重训与可学习属性

原 20,000 步已完成，[收敛续训阶段](rhythm-convergence.md)随后启动。维护者在累计约 23,900 步要求停止，转为旧版与两个新版最佳权重的实际谱面对照；最近完整状态保存在 23,000 步，未宣称达到收敛。原训练未保存优化器，续训使用新优化器，不能称为无缝恢复。最佳权重保留，独立验收与发布仍待完成。

## 2026-10-08 决定：停止技能标签路线，先修复表示与监督缺口

M1 社区技能标签试验未通过长串保留和条件响应门槛。按维护者决定，停止将这条路线作为待发布功能；下文 M1.1–M1.4 仅保留历史方案，**不再是执行队列**。问题是现有技能监督不足以支持可靠控制，并非所有谱面属性都缺乏监督。旧 S1 的密度 / 跨度启发式也不能被描述为已学会技能类型。

新方向在 [issue #10](https://github.com/kanze1/AUTO-OSU/issues/10) 跟踪：恢复原谱已有属性，比较音频上下文与事件表示，使用与实际推理一致的验证条件，再从头训练、实测并发布候选版。首轮四案例选型已完成，四卡正式重训已启动；重训完成、最终质量验收和新权重发布尚未完成。

### 已验证的数据事实

全语料按音频字节、来源音频身份、beatmapset 与非空规范化作者 / 歌名传递分组后，训练 / 验证 / 测试分别为 125,230 / 6,669 / 7,013 张谱面，25,235 / 1,372 / 1,408 个歌曲组。98 张谱面缺少有效文字身份，仍按音频和集合身份分组；没有将空文字身份合并。声学近重复未穷尽，v0 的预训练暴露仍不能由新划分消除。

从冻结验证清单依序取 128 个不同歌曲组、每组一张谱面，核对原文哈希后直接统计：57,130 个物件中有 21,711 个附加音效标记、14,112 个 new-combo 标记；23,674 条滑条中有 2,997 条折返滑条，22,016 条显式端点音效字段，1,849 条超过两个内部控制点。还存在 Kiai、SV 和采样属性。详见[原始属性盘点](rhythm-v1-attribute-audit-20261008.json)。这是字段覆盖盘点，不是标注质量或模型效果验收。

### 硬编码分类与替换方向

| 当前行为 | 所在路径 | 可用监督和替换方向 |
| --- | --- | --- |
| 按长度阈值和固定概率选择 L / B / P 曲线、0–2 个内部点 | `autoosu/ml/coord_infer.py::_slider_structure`，AI 路径也使用 | 原谱已有曲线、锚点与折返数；学习结构分布，再条件生成坐标；不要只替换随机概率 |
| AI 节奏只产生六种 tick 类别，折返默认一次，new combo 被规则重算 | `autoosu/ml/dataset.py`、`autoosu/ml/sample.py`、`autoosu/rhythm.py` | 原谱可监督折返和连击；现有预处理保存 new combo 但 tick 目标未使用，其他属性需要重新提取 |
| 鼓点阈值添加 clap / finish / whistle；滑条端点全部写零 | `autoosu/rhythm.py::_combos_and_hitsounds`、`autoosu/beatmap.py::Slider.to_line` | 分开处理导出丢失和模型未学习；先保留并学习 hitsound / 端点属性，再评估音效；自定义音频文件本身需要另查素材是否存在 |
| 1/4 拍六分类网格，偏离网格的物件可能被丢弃 | `autoosu/ml/dataset.py::build_ticks` | 属于表示容量限制；比较带时间偏移或事件时间的表示，不能靠放松采样阈值解决；保留节拍作为输入先验 |
| 能量阈值、最少四小节、最多两个 highlight；固定密度 / 跨度加成 | `autoosu/controls.py` | Kiai、局部密度、SV 可监督；Kiai 是谱师标记，不等价于副歌或理想 highlight；软条件与人工明确指定区间分开 |
| 连打密度 ×1.5、跨度 ×0.8；跳跃跨度 ×1.2 | `autoosu/preferences.py` | 停止用这些系数证明技能类别已学习；保留可解释的密度、距离等连续用户控制 |
| 孤立难度尖峰、时间重叠统一作为候选拒绝条件 | `autoosu/controls.py::candidate_rejections` | 与文件有效性拆开；结合难度、上下文和意图作软评分，并记录惩罚；重叠不自动等于损坏文件 |
| 坐标逐步裁剪、按画面适配滑条，必要时修改 SV | `autoosu/ml/coord_infer.py` | 学习几何与软代价，报告投影幅度和修复率；头部可达性与控制点范围分开，不能把所有锚点越界称为格式非法 |

纯规则引擎另有最大密度、串长和移动模板；它们不能直接当作 AI 模型路径的上限。默认预设的 AR / OD / CS / HP 也不是从音频推断的；先作为明确用户 / 难度条件，后续才评估自动推荐。

### 保留的硬约束与案例判定

文件可解析、数值有限、类型字段和引用有效、滑条时长 / 长度 / 折返的几何与时间关系一致，保留明确校验。生成结果仍需符合用户选择的支持范围。接近屏幕边缘、节奏密集、局部尖峰、长滑条或复杂曲线不能仅因少见就统一删除。序列语法有效性可以硬约束，事后改写模型结果的修复率则必须报告。

新的案例应把两类变化分开：同表示下比较音频编码器；固定编码器比较恢复属性监督 / 事件表示。最初的 flat / context2 / spectral2 / context4 仅覆盖第一类问题，因此执行配方修订如下；首轮属性监督仍不能解决自由时间表示。

### 首轮执行配方（2026-10-08）

执行候选修订为 `flat`、`context2`、`attributes`、`spectral_attributes`：前两者不含属性头，后两者分别使用线性 / 卷积音频前端及两层音频上下文，联合预测 new combo、标准头部 / 尾部附加音效、折返数和滑条结构。四者总 Transformer 层数均为八，宽度 512；均随机初始化，不继承失败的 M1 权重。该轮仍保留 1/4 拍表示；自定义声音素材、采样组、音量和中间折返点音效不在首轮学习范围内。

源属性已覆盖训练集中 56,537,662 个物件的连击 / 音效及 24,119,962 条滑条的尾音 / 折返 / 结构。无法对齐或存在歧义的 36,965 个训练物件不提供属性损失，原节奏样本保留。类别表只从训练集建立；验证集中 689 条未见过的结构、1 个未见过的折返类别保持未知，不改写为常见类别。完整结果见[属性准备报告](rhythm-v1-attributes-20261008.json)。覆盖数是对象级，不代表全部进入 1/4 拍训练网格。

四个候选各用一张 GPU，3,000 updates、batch 32、512 ticks、seed 1008，AdamW 初始学习率 3e-4、warmup 200、cosine decay。参考密度以 50% 概率隐藏，25% 序列完全 mask；属性损失为各适用头交叉熵的均值，系数 0.5。每 500 updates 在同一批 128 个独立验证歌曲组上以未知密度、中心裁剪、12 轮实际生成评估。属性同时报告参考物件条件下 NLL / accuracy 与生成物件匹配后的计数；不得将前者说成端到端属性准确率。

训练清单前 4,096 张谱面的属性频率作为固定先验对照。进入扩大训练的条件预先定为：至少三个属性头的验证 NLL 优于该训练频率先验，并且生成 onset F1 不低于两个无属性对照中最好值减 0.02；通过者按验证 onset F1 选取。该容忍幅度是探索选型门槛，不是发布或人评通过标准；单种子结果不证明架构普遍最优。若无候选通过则停止扩大训练，不自动重跑。

通过后，所选属性架构使用四卡 DDP 再次从随机初始化训练 20,000 updates，每卡 batch 32、1024 ticks、warmup 1,000；每 1,000 updates 使用同一验证歌曲组评估并保存 best / last。测试集不参与选型。训练成功后仍需冻结模型、独立测试、实际导出、运行时兼容及发布验收，调度器不会自动发布。

### 首轮实际结果与正在执行的训练

四案例均完成 3,000 updates。各自最优验证 onset F1：flat 0.659438、context2 0.650788、attributes 0.648719、spectral_attributes 0.649210。两个属性模型均在全部五个属性头上优于固定训练频率先验，且符合 0.02 的节奏容忍门槛；按预注册规则选取 spectral_attributes。其节奏 F1 比原始结构低约 1.02 个百分点，不能称为节奏质量提升；该选择是在增加可学习属性后继续扩大训练的探索决定。

195 项本地测试通过，四 rank DDP 前后向已运行。另用 attributes 的早期 step-500 checkpoint，对四首开发歌曲各截取前 30 秒实际生成，得到 471 个物件、378 条滑条、16 条折返滑条。独立 slider parser 确认物件数、头尾音效和折返一致；每条曲线 1,001 点检查均有限且在画面内。检查过程中第三方 parser 出现中间除法警告，未产生最终采样点非有限结果；没有声称 osu! 客户端试玩。该检查验证数据传递与导出，不替代最终权重的完整歌曲质量验收。数值和哈希见[案例报告](rhythm-v1-cases-20261008.json)。

训练 / 验证 / 测试固定歌曲组；选型和 checkpoint 只用验证集。评估默认不提供参考谱密度，使用完整生成而非仅 masked-token loss。原谱属性预测与生成物件属性匹配分别评估；记录稀有属性召回、概率校准、分布坍缩、结构修复率、推理开销和逐歌回归。验证集选型后冻结最终模型，再进行测试集与真实歌曲导出，独立解析和实际 osu! 试玩分开。对测试集结果调参后不得继续称其独立测试。

## M1.1：标签和数据审计

先统一标签含义：跳跃、短串、长串、耐力、滑条技巧、阅读等；首轮只选数据和标注质量足够的类别，允许多标签，也允许未知。短串与长串分开统计，不能用高密度直接代替连打标签。滑条数量偏好与滑条技巧分开。

- 建立数据清单：谱面和音频身份、实际星级、BPM、物件组成、标签来源、版本与使用条件；统计缺失、分歧和各星级段覆盖。
- 人工复核抽样，记录标注者一致性；社区标签与自动提取特征作为不同证据。缺标签不等于负标签，第一轮不提供缺乏负样本支持的“排除某技能”。
- 按音频内容分组，并检查同曲不同编码、剪辑和近重复，冻结训练 / 开发 / 测试清单。已经用于调参或验收的歌曲单列；v0 训练集交叠不明时明确标注。
- 保留静段、恢复段和高星样本，检查标签与星级、BPM、谱师的混淆，避免“偏跳跃”仅学成“更高星”。

产物：标签规范、数据统计、人工抽检记录、冻结划分及来源清单。标签质量或覆盖不足时先补数据，不直接启动完整重训。

## M1.2：小规模条件训练与消融

依赖 M1.1。在独立实验分支保留 v0 对照，先验证标签是否带来可重复的控制增益，再决定扩大训练规模。比较从 v0 微调与必要时重训的成本和结果，不默认全量从头训练。

1. 节奏模型增加技能标签条件，使用缺标签掩码和条件 dropout；保持现有星级、密度输入可用，检查无标签模式是否退化。
2. 坐标模型增加相同标签条件，保留逐 token 距离语义。比较仅节奏、仅坐标、双模型标签，以及当前条件版，分离标签本身的增益。
3. 单独评估细分节奏网格、滑条长度和段落条件，避免一次更换所有表示后无法归因。只有现有网格限制目标技能时才推进更细网格。

产物：可复现配置、数据版本、种子、曲线和逐歌对照。新 checkpoint 使用独立版本，模型文件不进 Git，不覆盖 v0。

## M1.3：冻结模型后的独立验收

依赖 M1.2。在开发集冻结权重、采样配置、候选策略和判定阈值，再使用预留集一次验收；修改策略后另取测试集。

- 同歌、同种子，比较无标签 / 正向标签 / 当前条件版，按**实际星级接近**分组报告技能响应和未满足率；分开短串、长串及不同星级段，不能只报平均星级提升。
- 参考 timing 与自动 timing 分开；6–7★、7–8★及更高星逐档检查，不把较低难度结论直接推广。
- 盲测记录偏好是否清楚、节奏自然度、可读性、疲劳与恢复段；人工 highlight 位置、客户端导入、试玩和编辑器另存分别留证。
- 回归综合模式、手动密度 / 跨度、四种 highlight、单首 / 批量、CPU / GPU、来源标签和新图水印；独立 parser 检查滑条路径与结构。

产物：冻结测试报告和人工评审记录。客观响应、目标星级和结构验收沿用既有口径；细分标签、人评样本量及通过标准在测试前登记。未通过时保留实验状态，不替换默认权重。

## M1.4：新权重候选版与发布

**2. 来源检测：先明确能回答什么**

当前 `autoosu/beatmap.py:124` 默认写入 `autoosu ai-generated kanzei`，Creator 可由用户修改。没有生成记录、内容指纹或检测入口；规则生成也继承同一个 AI 标签，无法区分使用了哪个模型。

建议软件中的入口叫“检查谱面来源”，接收 `.osu`、`.osz` 和目录。分别报告以下证据，避免把一个分数写成确定的作者判断：

| 证据 | 能回答的问题 | 结果用语 |
| --- | --- | --- |
| 文件里的标签和生成清单 | 文件声明由什么工具、模型生成 | “包含 AUTO-OSU 标识” |
| 与本机保存的生成记录匹配 | 内容是否与一次已记录输出一致 | “匹配本机生成记录”；注明记录范围 |
| 针对 v0 验证过的统计检测 | 删标识后是否仍有与 v0 输出相符的特征 | “发现与 AUTO-OSU v0 相符的生成特征”，显示证据与适用范围 |
| 缺少证据、短谱、其他模式或范围外输入 | 当前方法不能可靠判断 | “无法判断” |

未检出不能写成“人工谱面”。标签、模型文件 SHA-256 和随谱面附带的自述清单均可被复制，不能单独证明模型执行过；内容哈希只证明内容一致性。若将来需要第三方可验证的来源证明，需要可信的生成记录/签名方，签名密钥不能内置到公开客户端，而且签名任意上传文件本身也不能证明生成来源。

**D1 / P0：旧版 v0 检测可行性，先做第一轮实验。**

- 冻结发布权重、生成代码版本、种子及采样设置。正样本覆盖双模型、仅节奏模型、仅坐标模型和旧版本导出；这些模式分别记结果。
- 对照包括来源可核实的人工谱面、纯规则结果、Mapperatorinator 和其他生成器，尤其加入与我们共用坐标架构的结果，防止把“其他 AI”都判成“我们”。Ranked 身份本身不作为人工来源的充分证据。
- 第一轮建议固定 40–60 首不同类型歌曲、每首若干设置/种子，加至少 1,000 张人工对照。按歌曲/音频身份切分，进一步检查谱师重叠；同歌改版、同谱切片和多个种子不能跨训练与评估集合。
- 先比较两类轻量基线：节奏/滑条/几何统计，以及流水线留下的结构特征。元数据、文件名和格式差异单独记录，不能充当内容检测的捷径。
- 实验必须包含去除标识、编辑器重存、局部人工编辑和部分生成片段。先检验实际保留下来的证据，不预设“水印一定有效”。
- 若轻量基线有价值，再试节奏模型的掩码伪似然、坐标模型的一致性等白盒信号；人工谱本来就在模型学习的分布里，“模型认为合理”不能直接当作生成证据。
- 输出不同条件下的误报率、召回率、弃判率、耗时与错误样例。第一轮结束即给出继续/缩小范围/停止统计路线的结论，不无限延长试验。

进入软件前另设发布门槛：阈值只在校准集选择，独立保留至少 3,000 首不同歌曲的人工测试样本，并覆盖年代、谱师和难度；以误报率 0.1% 为目标，同时报告置信区间、歌曲聚类和其他生成器的错误归因率。3,000 次独立试验零误报的一侧 95% 上界仍约为 0.1%，不等于真实误报为零。召回不足就收窄支持范围，不能为了展示效果下调阈值。局部片段扫描需要单独校准整张图的误报。

**D2 / P0：新输出生成标识与本机记录。**

- 记录应用版本、引擎、节奏模型/坐标模型各自的哈希、种子及实际参数；明确 model / rules / mixed / custom-model。
- `.osu` 保留可见生成标签；`.osz` 附带版本化的生成清单；本机另存输出记录与内容指纹。
- 定义规范化内容指纹：明确纳入物件、timing、难度等玩法字段；把标题、谱师名和无关格式作为可独立修改的字段。保存原始文件哈希和规范化内容哈希，避免把两种匹配混为一谈。
- 不占用 `.osu` 的 Source 字段：官方格式规定它是歌曲原作来源。参考 [.osu 格式说明](https://osu.ppy.sh/wiki/en/Client/File_formats/osu_(file_format))。
- 接入 CLI 和 GUI，支持批量导出 JSON 报告。先上线标签/记录检查；D1 通过独立评估后才加入统计结果。
- 验收覆盖单曲、批量、GUI、CLI、CPU、独立 GPU worker，以及 osu! stable/lazer 的导入、重存、重新打包。重存丢失清单时要能如实降级；旧图仍能检查现存标签。

涉及 `beatmap.py`、`package.py`、`generate.py`、`models.py`、`batch.py`、`worker.py`、`cli.py`、`gui.py`、`i18n.py`，新增独立的来源解析模块。模型哈希按实际加载文件计算和缓存，不只信文件名。

若最终选择仅向工作人员提供进阶检测器，其参数和阈值就不能同时随公开 exe 分发。公开软件中的来源检查与受限检测包可以独立打包；等 D1 有有效结果后再决定分发方式，本轮不联系任何第三方。

本次只读统计本地 `data/prep/index.jsonl` 的 15,012 张谱面：小于 6★ 为 13,399；6–7★ 为 1,193；7–8★ 为 303；8–9★ 为 86；9★及以上为 31。这是本地子集，不是全量 14 万训练集的重新统计。它与历史设计文档提示一致：高星样本覆盖需要专门核查和补齐。

本次还用现成环境中的 `rosu-pp-py 3.1.0`（NM、stable 模式）重算了 8 张本地历史输出：7 张名为 Hard 的结果为 3.838–4.736★，一张 Normal 为 2.960★。文件身份与计算设置保存在 [baseline-2026-09-24.json](baseline-2026-09-24.json)。这些不是同一条件下新生成的受控实验，只用于证明实际星级能够接入测量，不能当作高星成功率或模型退化结论。

**Q1 / P1：固定评估集和实际星级报告。**

- 固定 20–30 首不参与调参的歌曲，覆盖平稳节奏、快歌、三连音、动态压缩强的歌和短爆点；人工标记主要 highlight。开发/调参歌曲另留一组。
- 固定星级计算器版本、stable/lazer 口径、mods 和生成设置。分别跑“人工 timing”和“自动 timing”，区分音乐定时错误与模型错误。
- 先测 5.5、6、6.5、7、7.5、8★条件响应，不先假定星级和 NPS 单调。记录实际 SR、aim/speed、局部 strain、连打长度、重叠/越界/滑条修正和耗时。
- 节奏评估分别报告真实密度、未知密度、预测密度；保留 F1 作为参考，同时评估段落变化和实际游玩反馈。
- 输出可复跑报告，接入软件的实际星级显示；不把模型条件继续显示成已测星级。

**Q2 / P1：先打通 6–7★控制，再扩展 7–8★。**

- 基于 Q1 找到有效的星级、密度、跨度组合，并允许“跳跃为主 / 连打为主 / 均衡”的独立目标；避免只提高全曲物件数。
- 将密度条件扩为逐段曲线，保留静段和恢复段。训练密度经过约 ±8 小节平滑，第一版曲线要匹配训练尺度；短爆点留给后续更细条件。
- 恢复坐标模型的可选距离条件，严格复用训练中的逐 token 定义、单位和缩放，包含滑条锚点，不直接把“物件间距离”填满所有 token。先验证它是否服从条件及是否损伤手感。
- 允许少量候选生成后测实际 SR，选择符合目标的结果；设定重试/耗时上限，仍达不到时显示实际值。不能为凑星级制造离谱尖峰。
- 在生成后做共同的玩法有效性检查。新增高难度预设应在这些结果验证后进行。

初步产品验收目标：在适合该难度的固定曲集上，至少 80% 输出落在目标 ±0.5★，并同时通过结构有效性与盲测；这是待验证目标。按歌曲报告失败例、峰值分布和实际额外耗时，单纯达到 SR 不算完成。

**H1 / P1：highlight 的音乐段落控制，先做原型。**

- 先支持手工指定时间范围与强度，用来单独验证“生成器能否做出强调”；自动定位作为另一项实验，避免两个问题混在一起。
- 用同一个段落计划驱动密度、跳跃/连打倾向、跨度、combo、hitsound 和 kiai，并安排进入前铺垫与结束后释放。kiai、SV 和整体难度曲线分别控制，不能只靠加速滑条来表现高潮。
- 自动定位在响度之外加入鼓/旋律 onset、和声变化、重复段落和小节边界；低置信度允许不添加或由用户调整，不强制每首歌都有明显 highlight。
- 同歌同种子做四组：当前版本；手工区间+密度；手工区间+密度/跨度；自动区间+全部控制。比较定位误差、段落对比、重复段落一致性和盲测偏好。
- 后续加入短片段重生成和边界衔接，保留用户满意的段落；这需要正确管理节奏上下文、坐标窗口、滑条跨段及局部 RNG，不作为首版原型的隐含完成项。

完成条件：人工标注/试听认可位置和段落对比；非 highlight 部分仍自然；重叠、滑条和局部 strain 不恶化。单纯 kiai 点亮或 NPS 提高不算完成。

**M1 / P2：数据和模型升级，按 Q1/Q2/H1 的失败原因启动。**

- 重算全量语料的高星覆盖、实际 SR 和量化损失，补齐 6–8★及更高星的歌曲/风格，分层采样；分割按音频身份，检查同歌跨谱包重复。
- 比较能覆盖 1/4、1/8、1/12 的多网格/自适应表示。单改成 1/12 仍不能覆盖 1/8；统一 1/24 可以表达更多，但 tick 数为现在 6 倍，先测覆盖收益、冲突率和显存，再选表示。
- 加入更细粒度密度、乐句/段落意图、局部模式和跨度条件；坐标 v1 同时加入要求的滑条长度，减少后处理变形。
- 多红线 timing 先作为可导入/可指定的独立能力，再评估自动预测。变速歌的 timing 失败不能靠扩大生成模型掩盖。
- 每个模型改动保留单变量对照，只有固定评估和盲测都提升才替换发布权重；同时为新权重重新评估检测器适用范围。
